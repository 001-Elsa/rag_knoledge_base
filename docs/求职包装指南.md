
## 四、面试 STAR 故事模板（背熟 2-3 个）

**故事 1：检索不准怎么办（AI 岗必问）**
- S：测试时发现"XR-500 保修多久"这类带型号的问题经常检索不到；
- T：提高专有名词类查询的召回率，且不能牺牲语义类问题的效果；
- A：分析发现纯向量检索对精确词不敏感 → 加关键词召回一路 → 用 RRF 融合免调权重；
  用评估脚本验证：Hit Rate 从 __ 提升到 __；
- R：两类问题都能命中，且整套评估流程沉淀成了脚本，后续每次改动都能回归。

**故事 2：上传大文件把接口卡死（后端岗必问）**
- S：50 页 PDF 上传后接口超时，前端一直转圈；
- T：上传必须秒回，处理进度要让用户看得到；
- A：接口只做流式落盘+建记录，重活丢 Celery；状态经 Redis 发布订阅推 WebSocket；
  任务做幂等（先删旧切片）+ acks_late 防丢；
- R：上传响应从 30s+ 降到 200ms 内，处理进度实时可见。

**故事 3：DeepSeek 偶发超时拖垮整个服务（可靠性）**
- S：LLM 偶发 30s+ 超时，请求堆积、线程耗尽；
- T：LLM 故障不能影响其他接口；
- A：客户端超时 + 有限重试 + 熔断器（连续失败快速失败、冷却半开恢复）；
  改写/追问这类增强功能全部做静默降级——增强不可用时核心问答仍然工作；
- R：LLM 全挂时其他接口 P95 无变化，恢复后自动闭合。
