# 升级说明

## v4.0（当前版本）：生产就绪 + 检索/记忆深度

| 变更 | 解决的问题 | 面试话术要点 |
|---|---|---|
| 关键词召回升级为 PG 全文检索 | LIKE '%kw%' 无法走索引，数据量大后 O(n) 全表扫描 | 入库时 jieba 分词写 tsvector（simple 解析器天然支持中文）+ GIN 倒排索引，查询 to_tsquery OR 连接 + ts_rank 排序；含 tsquery 特殊字符过滤（防注入）；Alembic 0002 增量迁移 + backfill_tokens.py 回填存量 |
| 长对话滚动摘要 | 几十轮后全量历史进 Prompt token 爆炸，只带最近几轮又"失忆" | Prompt = 摘要 + 最近 6 轮原文；超阈值增量压缩（旧摘要+新增轮次合并），summary_upto 记录覆盖位置；失败静默下轮重试 |
| 多模型容灾路由 | 主模型宕机/熔断期间服务完全不可用 | 调用顺序：主模型重试 → 熔断打开直接跳备胎 → 备用模型（任意 OpenAI 兼容服务）；流式与非流式都覆盖 |
| Prometheus + Grafana 大盘 | 指标只有裸 /metrics，没有可视化 | compose --profile monitoring 一键起，预置仪表盘：QPS、HTTP P95、检索 P95、LLM 首字 P95、错误率 |
| Caddy 反代 + 生产部署文档 | 项目只能本机跑，没有线上 demo | --profile edge 一键反代，配域名自动 HTTPS（Let's Encrypt）；《生产部署.md》从买服务器到上线检查清单 |
| 安全加固 | — | CORS 白名单（默认关）、nosniff/X-Frame-Options/Referrer-Policy 安全头 |

数据库结构有增量变更：`alembic upgrade head` 即可（0002 迁移）；存量切片跑一次 `python scripts/backfill_tokens.py`。

## v3.0：主打项目化

**AI 能力**

| 变更 | 说明 |
|---|---|
| Agent 模式 | Function Calling 多步工具循环（检索/查文档清单），模型自主决定检索策略，步数上限护栏，工具调用过程 SSE 实时可视化 |
| 语义缓存 | 相似问题（余弦相似度≥0.95）直接秒回缓存答案；知识库变更自动整体失效；Redis 故障降级为不走缓存 |
| 多查询扩展 | 问题自动扩展 2 个同义变体分别向量召回，统一 RRF 融合（默认关，评估后按需开） |
| 评估闭环 | gen_eval_set.py 从切片自动反向出题；eval_answers.py LLM-as-judge 评忠实度/相关性 |

**后端工程**

| 变更 | 说明 |
|---|---|
| LLM 容错三件套 | 客户端超时 + 有限重试（退避）+ 熔断器（连续失败快速失败、冷却恢复） |
| 全链路请求 ID | contextvar 贯穿单次请求所有日志，响应头回传 X-Request-ID |
| 压测脚本 | Locust 场景（多用户注册、读接口混合负载），配套简历数据填写指引 |
| CI | GitHub Actions：ruff lint + pytest（CI 专用轻量依赖清单，不装 torch） |
| 开源规范 | MIT License、ruff 配置 |

**前端**：模式切换（问答/Agent）、Agent 工具调用时间线、缓存命中标识、停止生成（AbortController）、重新生成、会话重命名。

**新文档**：《求职包装指南》——GitHub 仓库摆法、分岗位简历模板、STAR 故事、实测数据获取步骤。

v3 无数据库结构变更，从 v2 升级无需迁移。

## v2.0 升级说明

v1 → v2 的完整变更清单，方便对照理解每个模块为什么存在（也是面试讲"项目演进"的素材：
先跑通最小链路，再按痛点逐项演进，这个叙事本身就是加分项）。

## 功能新增

| 变更 | 解决的问题 | 涉及模块 |
|---|---|---|
| 多知识库管理 | 所有文档混在一起，无法按主题隔离检索 | models.KnowledgeBase、routers/kb.py、检索层 kb 过滤 |
| 多轮查询改写 | "那第二条呢"这类指代问题检索不到内容 | llm.rewrite_query，SSE `rewrite` 事件 |
| PDF 页码级引用 | 引用只到"第几段"，用户无法回原文核对 | parser 按页解析、Chunk.page、来源标注 |
| 推荐追问 | 用户问完一句就不知道还能问什么 | llm.suggest_followups，SSE `suggestions` 事件 |
| 用量统计看板 | token 花在哪、延迟多少完全黑盒 | UsageRecord、routers/stats.py、ECharts 图表 |
| WebSocket 实时通知 | 前端 4 秒轮询浪费请求、状态更新慢 | services/notify.py（Redis 发布订阅）、routers/ws.py |

## 技术栈升级

| 变更 | v1 | v2 |
|---|---|---|
| 建表方式 | 启动时 create_all | Alembic 迁移（compose 里 `alembic upgrade head`）|
| 认证 | 单个 24h JWT，无法登出 | Access(30min) + Refresh(7d) 双 Token；Redis 白名单、GETDEL 原子轮换防重放、登出吊销 |
| 限流存储 | 进程内存（单实例） | 可配置 Redis（多实例全局限流） |
| 可观测性 | 仅请求日志 | Prometheus /metrics：HTTP 直方图 + 检索耗时 + LLM 首字延迟；健康检查探测 DB/Redis |
| 队列监控 | 无 | Flower 面板（localhost:5555） |
| token 用量 | 不采集 | stream_options include_usage 采集并落库 |

## 前端重做

- 原生 JS 单页 → Vue 3 + Element Plus（组件化状态管理，代码可维护）
- 前端依赖全部本地化（scripts/download_vendor.py 走 npmmirror），不依赖外网 CDN，内网可部署
- 新增：深色/浅色主题、Markdown 渲染（marked）+ 代码高亮（highlight.js）+ XSS 过滤（DOMPurify）、
  会话历史恢复、拖拽批量上传、实时状态通知、ECharts 用量图表
- 401 自动用 Refresh Token 换新并重试请求（无感续期）

## 升级到 v2 的注意事项

- **数据库结构有变化**（新增表与字段）。v1 的老库不能直接用：开发环境直接
  `docker compose down -v` 清掉旧卷重来最省事；有真实数据则需要手写迁移。
- 上传接口现在要求 `kb_id` 表单字段（先建知识库）。
- 登录接口返回结构从 `{access_token}` 变为 `{access_token, refresh_token}`。
