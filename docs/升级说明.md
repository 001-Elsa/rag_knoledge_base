# 升级说明

## 当前迁移状态与升级顺序

当前 Alembic head 是 `0009`。全新数据库直接执行：

```bash
alembic upgrade head
```

旧数据库按当前 revision 处理：

- `0001`：先升级到 `0002`，之后可运行 `scripts/backfill_tokens.py` 回填全文索引；
- `0002`：先升级到 `0003`，停止 API/Worker 写入，运行 `scripts/backfill_document_hashes.py`，再升级到 head；
- `0003`：停止 API/Worker 写入，运行 `scripts/backfill_document_hashes.py`，确认没有 NULL 后再升级到 head；
- `0004`～`0008`：备份后直接 `alembic upgrade head`。

`0004` 会把 `documents.content_hash` 设为 NOT NULL。迁移不会为历史文件伪造哈希；缺失的 legacy
`filepath` 会让回填脚本失败，需要先从原始来源恢复文件。生产升级前必须备份并做恢复演练。

## v5.0（当前仓库）：企业可靠性、多租户治理与安全闭环

| Revision | 主要变更 | 关键实现 |
|---|---|---|
| 0003 | 文档内容幂等 | `content_hash`、文档/切片唯一约束；进入 0004 前必须回填真实 SHA-256 |
| 0004 | 企业基础 | Transactional Outbox、细粒度文档状态机、版本索引、Organization/Workspace/RBAC、知识库/文档/Chunk/Audit RLS、追加式审计 |
| 0005 | Parent-Child Retrieval | `parent_seq` 与 `parent_content`，小切片召回后按父段去重扩展 |
| 0006 | Workspace 治理 | 同一 Organization 下 Workspace 名称唯一 |
| 0007 | 用户数据 RLS | Conversation、Message、UsageRecord 的 owner 隔离 |
| 0008 | 恢复与安全 | Dead Letter、Embedding pipeline fingerprint/checkpoint、文档隔离区、审计哈希链 |
| 0009 | 审计不可变权限 | 回收 `rag_app` 对 `audit_logs` 的 UPDATE/DELETE，只保留查询与追加 |

当前运行时还包括：对象存储最终一致删除、孤儿对象/陈旧租约对账、Prompt Injection 风险策略、可选
Claim-Evidence 校验、SLO recording rules、安全扫描与 SBOM。管理端所谓“从阶段续跑”不会跳过解析/切片；
它记录失败阶段并重新入队，流水线指纹一致时复用已提交的 Embedding checkpoint。

安全升级提醒：旧仓库没有 `.dockerignore`，如果曾在包含本地 `.env` 的目录执行 Docker build，旧镜像层
可能包含运行密钥。升级后应轮换相关 Secret，并执行 `docker compose build --no-cache` 后重新部署；旧镜像
在确认不再运行后按组织的镜像保留策略退役。

## v4.0：生产部署 + 检索/记忆深度

| 变更 | 解决的问题 | 实现说明 |
|---|---|---|
| 关键词召回升级为 PG 全文检索 | LIKE '%kw%' 无法走索引，数据量大后 O(n) 全表扫描 | Python 先用 jieba 做中文分词，再写入 `to_tsvector('simple', ...)` + GIN；查询使用 OR 连接的 to_tsquery + ts_rank；含 tsquery 特殊字符过滤；Alembic 0002 增量迁移 + backfill_tokens.py 回填存量 |
| 长对话滚动摘要 | 几十轮后全量历史进 Prompt token 爆炸，只带最近几轮又"失忆" | Prompt = 摘要 + 最近 6 轮原文；超阈值增量压缩（旧摘要+新增轮次合并），summary_upto 记录覆盖位置；失败静默下轮重试 |
| 多模型容灾路由 | 主模型宕机/熔断期间服务完全不可用 | 调用顺序：主模型重试 → 熔断打开直接跳备胎 → 备用模型（任意 OpenAI 兼容服务）；流式与非流式都覆盖 |
| Prometheus + Grafana 大盘 | 指标只有裸 /metrics，没有可视化 | compose --profile monitoring 一键起，预置仪表盘：QPS、HTTP P95、检索 P95、LLM 首字 P95、错误率 |
| Caddy 反代 + 生产部署文档 | 项目只能本机跑，没有线上 demo | --profile edge 一键反代，配域名由 Caddy 自动申请并续期 HTTPS 证书；《生产部署.md》从买服务器到上线检查清单 |
| 安全加固 | — | CORS 白名单（默认关）、nosniff/X-Frame-Options/Referrer-Policy 安全头 |

该阶段的数据库增量是 `0002`；存量切片需运行一次 `python scripts/backfill_tokens.py`。从更老版本直接
升级到当前 head 时，还必须遵循本文开头的 content hash 回填顺序。

## v3.0：主打项目化

**AI 能力**

| 变更 | 说明 |
|---|---|
| Agent 模式 | Function Calling 多步工具循环（检索/查文档清单），模型自主决定检索策略，步数上限护栏，工具调用过程 SSE 实时可视化 |
| 语义缓存 | 相似问题（余弦相似度≥0.95）直接秒回缓存答案；知识库变更自动整体失效；Redis 故障降级为不走缓存 |
| 多查询扩展 | 问题自动扩展 2 个同义变体分别向量召回，统一 RRF 融合（默认关，评估后按需开） |
| 评估闭环 | gen_eval_set.py 从切片自动反向出题；eval_answers.py LLM-as-judge 评忠实度/相关性 |

**后端工程**

| 变更 | 说明 |
|---|---|
| LLM 容错三件套 | 客户端超时 + 有限重试（退避）+ 熔断器（连续失败快速失败、冷却恢复） |
| 全链路请求 ID | contextvar 贯穿单次请求所有日志，响应头回传 X-Request-ID |
| 压测脚本 | Locust 场景（多用户注册、读接口混合负载），用于记录可复现的性能基线 |
| CI | GitHub Actions：ruff lint + pytest（CI 专用轻量依赖清单，不装 torch） |
| 开源规范 | MIT License、ruff 配置 |

**前端**：模式切换（问答/Agent）、Agent 工具调用时间线、缓存命中标识、停止生成（AbortController）、重新生成、会话重命名。

**文档调整**：补充架构、部署和版本升级说明。

## v2.0 升级说明

v1 → v2 的完整变更清单，用于对照理解每个模块的设计背景。

## 功能新增

| 变更 | 解决的问题 | 涉及模块 |
|---|---|---|
| 多知识库管理 | 所有文档混在一起，无法按主题隔离检索 | models.KnowledgeBase、routers/kb.py、检索层 kb 过滤 |
| 多轮查询改写 | "那第二条呢"这类指代问题检索不到内容 | llm.rewrite_query，SSE `rewrite` 事件 |
| PDF 页码级引用 | 引用只到"第几段"，用户无法回原文核对 | parser 按页解析、Chunk.page、来源标注 |
| 推荐追问 | 用户问完一句就不知道还能问什么 | llm.suggest_followups，SSE `suggestions` 事件 |
| 用量统计看板 | token 花在哪、延迟多少完全黑盒 | UsageRecord、routers/stats.py、ECharts 图表 |
| WebSocket 实时通知 | 前端 4 秒轮询浪费请求、状态更新慢 | services/notify.py（Redis 发布订阅）、routers/ws.py |

## 技术栈升级

| 变更 | v1 | v2 |
|---|---|---|
| 建表方式 | 启动时 create_all | Alembic 迁移（compose 里 `alembic upgrade head`）|
| 认证 | 单个 24h JWT，无法登出 | Access(30min) + Refresh(7d) 双 Token；Redis 保存一次性 jti，GETDEL 原子消费防重放、登出吊销 family |
| 限流存储 | 进程内存（单实例） | 可配置 Redis（多实例全局限流） |
| 可观测性 | 仅请求日志 | Prometheus /metrics：HTTP 直方图 + 检索耗时 + LLM 首字延迟；健康检查探测 DB/Redis |
| 队列监控 | 无 | Flower 面板（localhost:5555） |
| token 用量 | 不采集 | stream_options include_usage 采集并落库 |

## 前端重做

- 原生 JS 单页 → Vue 3 + Element Plus（组件化状态管理，代码可维护）
- 前端依赖全部本地化（scripts/download_vendor.py 走 npmmirror），不依赖外网 CDN，内网可部署
- 新增：深色/浅色主题、Markdown 渲染（marked）+ 代码高亮（highlight.js）+ XSS 过滤（DOMPurify）、
  会话历史恢复、拖拽批量上传、实时状态通知、ECharts 用量图表
- 401 自动用 Refresh Token 换新并重试请求（无感续期）

## 升级到 v2 的注意事项

- **数据库结构有变化**（新增表与字段）。仅对于确认无保留价值的开发数据，才可用
  `docker compose down -v` 删除卷后重建；该命令不可恢复。任何真实数据都应先备份并按本文开头的
  migration/backfill 顺序升级。
- 上传接口现在要求 `kb_id` 表单字段（先建知识库）。
- 登录接口响应模型包含 `{access_token, refresh_token}`；当前默认通过 HttpOnly Cookie 下发 Refresh Token，
  因此响应体中的 `refresh_token` 默认为 `null`，仅兼容模式 `EXPOSE_REFRESH_TOKEN_IN_BODY=true` 才返回明文。
